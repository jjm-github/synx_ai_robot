# Synx AI Robot

Кросс-платформенное нативное приложение (Python + FastAPI + pywebview) для
производства в synx: отслеживание публикаций, AI-разбор комментариев,
постановка задач ботам, очередь выполнения и публикация версий.

Интерфейс — настоящее desktop-окно (pywebview), не вкладка браузера. FastAPI
работает локально на `127.0.0.1` и отдаёт только локальный UI.

## Установка

```bash
cd /home/jaroslav/Dev/synx_ai_robot
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -r requirements.txt
```

На Linux для pywebview нужен GTK/WebKit2 (`python3-gi`, `gir1.2-webkit2-4.1`)
либо PyQt5. На Windows/macOS pywebview использует системный webview.

## Запуск

```bash
.venv/bin/python main.py
```

Для отладки без окна:

```bash
.venv/bin/python main.py --server-only --port 8777
# UI: http://127.0.0.1:8777/
```

## Настройки

- `config.json` — AI провайдер, synx, ComfyUI, конвейер, системный промпт.
- `bots.json` — отдельный список ботов: логин, пароль, роль, вкл/выкл.
- `prompts/system.md` — системный промпт (редактируется и из UI).
- `data/robot.sqlite3` — SQLite: публикации, задачи, события.

По умолчанию synx: `https://synks.ru/`, пользователь `p.robot`.
Пароль и пароли ботов задаются в настройках приложения (`config.json`,
`bots.json`); в репозиторий они не попадают.

## Как работает

1. **Публикации** — сканирование synx (вручную или автоматически по
   `scan_interval_sec`), новые комментарии версий и задач складываются в SQLite.
2. **AI-разбор** — выбранный комментарий (и вложения review-картинок)
   отправляется в OpenAI-совместимый провайдер. Модель возвращает JSON:
   название задачи, тип, бота, промпт, negative, workflow, references.
3. **Создание задачи** — через API synx создаётся задача, назначается бот.
4. **Конвейер** — задачи из очереди проходят этапы `analysis → generation →
   assembly → review → done`. Этапы, время и токены пишутся в SQLite; UI
   обновляет только активную строку каждые 5 секунд.
5. **ComfyUI** — если в задаче есть `workflow` или указан
   `comfy.workflow_path`, workflow отправляется в ComfyUI API. Поддерживаются
   плейсхолдеры `{{PROMPT}}`, `{{NEGATIVE}}`, `{{SEED}}`, `{{IMAGE}}`,
   `{{WIDTH}}`, `{{HEIGHT}}`, `{{FRAMES}}`, `{{SHOT}}`.
6. **Публикация** — при `auto_publish=true` версия публикуется от бота задачи.
   Иначе доступна кнопка «Опубликовать результат».

## Таблицы

Поведение таблиц повторяет synx_engine:

- ПКМ по заголовку — чекбоксы видимости колонок, сброс ширин, показать все.
- Перетаскивание правого края заголовка — ширина колонки.
- Ширины/видимость сохраняются в localStorage для каждой таблицы.
- Сортировка по клику на заголовок, фильтр по тексту.
- Мультивыбор строк чекбоксами.

## ПКМ по задаче

- открыть рабочую папку;
- пауза (текущая задача уступает следующей);
- продолжить;
- skip / unskip;
- опубликовать результат;
- удалить задачу;
- удалить задачу вместе с папкой;
- удалить все выполненные.

## Ограничения

- AI-провайдер должен поддерживать OpenAI-совместимый
  `POST /chat/completions` и (для review-картинок) vision-сообщения.
- Для реальной генерации нужен настроенный ComfyUI workflow. Без workflow
  задача завершится ошибкой на этапе generation — это сделано специально,
  чтобы не публиковать пустышки.
- `auto_publish` по умолчанию выключен: сначала проверяйте результат.
- Публикация выполняется от имени бота, назначенного на задачу; бот должен
  быть в `bots.json` и активен.


## ComfyUI

Приложение использует ComfyUI из `~/opt/ComfyUI` (пути можно изменить в
настройках). По умолчанию:

```text
base_url   http://127.0.0.1:8199
input_dir  ~/opt/ComfyUI/input
output_dir ~/opt/ComfyUI/output
```

Если ComfyUI запущен с другими `--input-directory/--output-directory`,
пропиши их в настройках. Встроенные workflow-билдеры:

- **FLUX.3 Klein i2v** — перерисовка/стилизация кадра по референсу;
- **FLUX.3 Klein t2i** — генерация кадра с нуля;
- **Wan 2.2 TI2V-5B i2v** — видео из первого кадра;
- **Wan 2.2 TI2V-5B t2v** — видео из текста.

Билдер выбирается по названию/промпту задачи: `wan/i2v/t2v/animate/video`
→ Wan 2.2, иначе FLUX.3. Любой из них можно переопределить полем
`workflow` в AI-плане или `comfy.workflow_path` в настройках.

## Структура рабочих файлов

Рабочие файлы ботов:

```text
<projects_root>/<project>/shots/<sequence>/<shot>/<task_type>/work/<bot>/<task_name>_vXXX/
```

Для Liberia:

```text
<projects_root>/<project>/assets/<shot>/<task_type>/work/<bot>/<task_name>_vXXX/
```

Рендеры (PNG/MP4 и отдельные файлы):

```text
<shot_dir>/render/vXXX/
```

Шаблоны путей настраиваются в `config.json` → `paths.layouts`.


## Чат

Страница **Чат** — диалог с моделью. Можно:

- задавать вопросы по производству и synx;
- прикреплять референсы (кнопка «+ Референс»);
- просить сгенерировать изображение: «нарисуй … по этим референсам»;
- получать картинку прямо в чате.

Генерация идёт через ComfyUI: FLUX.3 i2v при наличии референсов, иначе t2i.
Модель может вызвать инструмент `generate_image`; если провайдер не поддерживает
tool calling, работает fallback по ключевым словам.

Просмотр изображения:

- колесо — зум к курсору;
- средняя кнопка + движение — панорама;
- средний клик — сброс зума;
- ПКМ — «Сохранить как...» и «Копировать изображение».


## Synx-инструменты в чате

Чат использует данные Synx из настроек (`base_url`, логин, пароль) и умеет:

- `synx_projects` — список проектов;
- `synx_versions` — версии проекта за период;
- `synx_tasks` — задачи проекта;
- `synx_make_playlist` — плейлист Synx Player за период.

Плейлист формируется по формату `synx_engine`:

```text
<start synx playlist:
{"synx_playlist": 1, "items": [...]}
end synx playlist>
```

В чате он показывается карточкой с кнопкой **«Скопировать»**. Текст можно
вставить в плейлист Synx в браузере (Ctrl+V).

## Сессии чата

История чата хранится в SQLite и переживает перезапуск приложения. Каждая
сессия имеет свой контекст; сессии можно создавать и переключать в верхней
панели чата. Модель при каждом запросе получает историю текущей сессии.


## Темы

Кнопка **◐** в верхней панели открывает меню тем из synx_engine:

- Redmond;
- Ash;
- Dark;
- cs 1.6;
- своя тема.

Пункт **«Редактор тем…»** открывает диалог с загрузкой картинки-источника,
ручным выбором цветов, кнопкой **Sample!** (сэмплирование четырёх цветов
с картинки), предпросмотром, сохранением/загрузкой `.json` и применением.
Тема сохраняется в localStorage/куке и применяется при следующем запуске.


## Разметка публикаций

При сканировании новые комментарии автоматически отправляются AI-разметке
(`synx.auto_analyze`). Для каждого определяется:

- **продолжение** — нужна новая версия/генерация/исправление;
- **версия** — публикация версии, уведомление или положительный отзыв.

Если после комментария по тому же шоту уже выпущена версия (для комментариев
задачи — версия этой же задачи), комментарий считается **отвеченным версией**.
Такой комментарий не требует продолжения, задача по нему не предлагается и не
создаётся. При сканировании флаги отвеченных комментариев обновляются
автоматически, повторный ручной разбор не нужен.

В таблице публикаций есть колонка **«Тип публикации»** и фильтры:

- все события;
- с продолжением;
- просто версия;
- не разобрано;
- отвечено версией;
- с картинками;
- чекбоксы «Показывать версии» и «Показывать отвеченные».

Отвеченные комментарии по умолчанию скрыты из таблицы. Существующие
неразобранные комментарии можно отправить в AI-разметку кнопкой
**«Разметить AI»**.

### Приоритетные сообщения @p.robot

Сканер ищет упоминания `@p.robot` в комментариях версий, задачах,
комментариях сущностей и в свежей ленте событий synx. Такие сообщения
считаются приоритетными указаниями:

- помечаются в таблице бейджем **`@p.robot`** и фильтром
  «упоминания @p.robot»;
- всегда классифицируются как «с продолжением», даже если в тексте нет
  обычных слов-триггеров;
- автоматически ставятся в AI-разбор, который формирует конкретное
  руководство к действию (summary/prompt) на основе текста сообщения;
- задачи из таких сообщений получают приоритет и запускаются конвейером
  раньше обычных;
- если по сообщению уже выпущена версия, оно считается отвеченным и задача
  не создаётся.

## Ссылки на версии в задачах

После публикации версии задача получает ссылку вида:

```text
https://synks.ru/p/colossus?tab=tasks&t=shot-c004_0020-prod_gen-ink_watercolor&v=shot-c004_0020-v003
```

Она открывает проект Synx с выбранной задачей/шотом и версией в плеере.
Ссылка открывается во внешнем браузере через pywebview bridge.
