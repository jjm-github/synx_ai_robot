# Synx AI Robot

Кросс-платформенное нативное приложение (Python + FastAPI + pywebview) для
производства в synx: отслеживание публикаций, AI-разбор комментариев,
постановка задач ботам, очередь выполнения и публикация версий.

Интерфейс — настоящее desktop-окно (pywebview), не вкладка браузера. FastAPI
работает локально на `127.0.0.1` и отдаёт только локальный UI.

## Установка

```bash
cd /home/jaroslav/Dev/synx_ai_robot
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -r requirements.txt
```

На Linux для pywebview нужен GTK/WebKit2 (`python3-gi`, `gir1.2-webkit2-4.1`)
либо PyQt5. На Windows/macOS pywebview использует системный webview.

## Запуск

```bash
.venv/bin/python main.py
```

Для отладки без окна:

```bash
.venv/bin/python main.py --server-only --port 8777
# UI: http://127.0.0.1:8777/
```

## Настройки

- `config.json` — AI провайдер, synx, ComfyUI, конвейер, системный промпт.
- `bots.json` — отдельный список ботов: логин, пароль, роль, вкл/выкл.
- `prompts/system.md` — системный промпт (редактируется и из UI).
- `data/robot.sqlite3` — SQLite: публикации, задачи, события.

По умолчанию synx: `https://synks.ru/`, пользователь `p.robot`.
Пароль и пароли ботов задаются в настройках приложения (`config.json`,
`bots.json`); в репозиторий они не попадают.

## Как работает

1. **Публикации** — сканирование synx (вручную или автоматически по
   `scan_interval_sec`), новые комментарии версий, задач и сущностей складываются
   в SQLite. Отдельный быстрый монитор событий (`event_interval_sec`, по
   умолчанию 30 с) читает `/api/events` и добавляет новые комментарии и
   сообщения с `@p.robot` в таблицу, не дожидаясь полного скана.
2. **AI-разбор** — выбранный комментарий (и вложения review-картинок)
   отправляется в OpenAI-совместимый провайдер. Модель возвращает JSON:
   название задачи, тип, бота, промпт, negative, workflow, references.
3. **Создание задачи** — через API synx создаётся задача, назначается бот.
4. **Конвейер** — задачи из очереди проходят этапы `analysis → generation →
   assembly → review → done`. Этапы, время и токены пишутся в SQLite; UI
   обновляет только активную строку каждые 5 секунд.
5. **ComfyUI** — если в задаче есть `workflow` или указан
   `comfy.workflow_path`, workflow отправляется в ComfyUI API. Поддерживаются
   плейсхолдеры `{{PROMPT}}`, `{{NEGATIVE}}`, `{{SEED}}`, `{{IMAGE}}`,
   `{{WIDTH}}`, `{{HEIGHT}}`, `{{FRAMES}}`, `{{SHOT}}`.
6. **Публикация** — при `auto_publish=true` версия публикуется от бота задачи.
   Иначе доступна кнопка «Опубликовать результат».

### Мониторинг событий и автообновление таблицы

- Полный скан — по `synx.scan_interval_sec` (по умолчанию 300 с).
- Быстрый монитор событий — по `synx.event_interval_sec` (по умолчанию 30 с),
  лимит событий `synx.event_limit` (200). Он вставляет новые комментарии,
  комментарии с `@p.robot` и обновляет флаги отвеченных.
- При следующем полном скане подтягиваются вложения и полный текст.
- UI опрашивает `/api/publications/changes` каждые 10 секунд и добавляет новые
  строки в таблицу без перезагрузки, сохраняя выбранные строки и фильтры.
- Новые `@p.robot`-сообщения сразу попадают в таблицу как приоритетные.

## Таблицы

Поведение таблиц повторяет synx_engine:

- ПКМ по заголовку — чекбоксы видимости колонок, сброс ширин, показать все.
- Перетаскивание правого края заголовка — ширина колонки.
- Ширины/видимость сохраняются в localStorage для каждой таблицы.
- Сортировка по клику на заголовок, фильтр по тексту.
- Мультивыбор строк чекбоксами.

## ПКМ по задаче

- открыть рабочую папку;
- пауза (текущая задача уступает следующей);
- продолжить;
- skip / unskip;
- опубликовать результат;
- удалить задачу;
- удалить задачу вместе с папкой;
- удалить все выполненные.

## Ограничения

- AI-провайдер должен поддерживать OpenAI-совместимый
  `POST /chat/completions` и (для review-картинок) vision-сообщения.
- Для реальной генерации нужен настроенный ComfyUI workflow. Без workflow
  задача завершится ошибкой на этапе generation — это сделано специально,
  чтобы не публиковать пустышки.
- `auto_publish` по умолчанию выключен: сначала проверяйте результат.
- Публикация выполняется от имени бота, назначенного на задачу; бот должен
  быть в `bots.json` и активен.


## ComfyUI

Приложение использует ComfyUI из `~/opt/ComfyUI` (пути можно изменить в
настройках). По умолчанию:

```text
base_url   http://127.0.0.1:8199
input_dir  ~/opt/ComfyUI/input
output_dir ~/opt/ComfyUI/output
```

Если ComfyUI запущен с другими `--input-directory/--output-directory`,
пропиши их в настройках. Встроенные workflow-билдеры:

- **FLUX.3 Klein i2v** — перерисовка/стилизация кадра по референсу;
- **FLUX.3 Klein t2i** — генерация кадра с нуля;
- **Wan 2.2 TI2V-5B i2v** — видео из первого кадра;
- **Wan 2.2 TI2V-5B t2v** — видео из текста.

Билдер выбирается по названию/промпту задачи: `wan/i2v/t2v/animate/video`
→ Wan 2.2, иначе FLUX.3. Любой из них можно переопределить полем
`workflow` в AI-плане или `comfy.workflow_path` в настройках.

## Структура рабочих файлов

Все рабочие файлы генерации — PNG/JPG, видео, workflow JSON, PDF, meta,
README — лежат под задачей, в папке бота, назначенного на задачу:

```text
<projects_root>/<project>/shots/<sequence>/<shot>/<task_type>/work/<bot>/<task_name>_vXXX/
```

Для asset-сущностей:

```text
<projects_root>/<project>/assets/<asset>/<task_type>/work/<bot>/<task_name>_vXXX/
```

Финальные рендеры (PNG/MP4/PDF и отдельные файлы):

```text
<shot_dir>/render/vXXX/
```

Нельзя складывать рабочие файлы в корень проекта, `render/` без `vXXX` или
произвольные папки. Превью в `data/chat` — временное; канонические файлы
задачи — только в папке задачи/бота.

Шаблоны путей настраиваются в `config.json` → `paths.layouts`.


## Чат

Страница **Чат** — диалог с моделью. Можно:

- задавать вопросы по производству и synx;
- прикреплять референсы (кнопка «+ Референс»);
- просить сгенерировать изображение: «нарисуй … по этим референсам»;
- получать картинку прямо в чате.

Генерация идёт через ComfyUI: FLUX.3 i2v при наличии референсов, иначе t2i.
Модель может вызвать `generate_image` или `generate_from_synx_version`; если
провайдер не поддерживает tool calling, работает fallback по ключевым словам.

### Генерация из версии synx

Запрос вида «найди в проекте colossus версию p002_0130 v004, загрузи её как
референс и сгенерируй картинку в стиле кубизм с сохранением композиции и
пропорций» обрабатывается одним проходом:

1. `synx_find_version` ищет шот и версию; если в указанном проекте шота нет,
   поиск автоматически идёт по остальным проектам (с пометкой
   `project_corrected`);
2. версия скачивается в `data/refs/versions/<project>/`;
3. для видео извлекается средний кадр, для изображения берётся исходник;
4. размер генерации считается по пропорциям исходника (с ограничением по
   стороне/мегапикселям), затем результат аккуратно кадрируется до точного
   aspect ratio исходной картинки;
5. FLUX.3 i2v собирается с `workflow_config`: `profile`, `steps`, `cfg`,
   `denoise`, `megapixels`, `preserve_aspect`, `style`, `models`
   (`unet`/`clip`/`vae`).

Тот же `workflow_config` можно вернуть в AI-плане задачи — конвейер применит
его в `build_for_task`, не меняя остальные задачи.

Ссылки в чате и планах открываются во внешнем браузере, а не внутри окна
робота. Локальные пути файлов (PDF/PNG/видео) кликабельны и открываются в
системном просмотрщике.

Просмотр изображения:

- колесо — зум к курсору;
- средняя кнопка + движение — панорама;
- средний клик — сброс зума;
- ПКМ — «Сохранить как...» и «Копировать изображение».


### PDF из кадров и публикация версии

Робот умеет склеивать отдельные картинки в многостраничный PDF — по одной
картинке на страницу — и публиковать его как версию:

- `make_pdf_from_images` — собрать PDF из последних картинок чата или явных путей;
- `publish_images_as_version` — собрать PDF, создать задачу в synx (по умолчанию
  `Art`), выбрать и назначить бота по скилам из synx API, разложить PNG и
  workflow JSON в рабочую папку задачи и в `render/vXXX` шота, затем
  опубликовать PDF от имени бота.

Пример: 5 кадров → PDF на 5 страниц (2062×864), задача `cubism_frames`, бот
`e.matveev` (Render, AI), версия `v005` в Liberia / p002_0130.

### Daily PDF

Отдельный базовый layout для дэйли (контактный лист + карточки кадров):

- страница 1 — все кадры мелко;
- далее по одному кадру на страницу, фон чёрный, кадр по ширине листа
  (боковые края совпадают с границами);
- под кадром серым текстом (белый ~50%): Prompt EN/RU, модели и LoRA,
  время генерации, PC/GPU/VRAM/CPU/RAM/SWAP, стоимость API, длина видео,
  разрешение;
- те же данные попадают в комментарий публикуемой версии;
- PDF проверяется: число страниц, A4 842×595 pt, пустые страницы.
- 300 dpi поддерживается (страницы остаются A4 по точкам, картинка рендерится
  с 300 dpi).
- PDF-просмотр в роботе: `pdf_render_pages` параллельно рендерит все страницы
  в кэш PNG (`data/pdf_cache/...`), а встроенный viewer показывает уже готовые
  страницы с зумом/панорамой, не дожидаясь полной загрузки PDF.
- Пересборка по базовой версии: если пользователь говорит «версия 13,
  исправь…», робот берёт кадры задачи и вызывает `publish_daily_pdf` с
  `base_version`, `dpi`, `text_scale`, `image_valign`, `background`, не
  генерируя изображения заново.

Инструмент: `publish_daily_pdf` (или `daily_pdf.make_daily_pdf` +
`publish_flow.publish_daily_pdf`). Пример: v013 в Liberia / p002_0130 —
6 страниц, чёрный фон, подписи и железо.

### ffmpeg и MCP

`ffmpeg`/`ffprobe` установлены и являются базовыми инструментами: нарезка,
склейка, кадры, слайдшоу, проверка видео — прямыми вызовами. MCP-серверы можно искать/устанавливать/редактировать в приложении, а включённые
серверы вызываются из чата через `mcp_list_tools` / `mcp_call`.

Для ComfyUI включён **`artokun/comfyui-mcp`** — 41 инструмент:
`create_workflow` (create/modify/validate), `download_model` (HuggingFace/CivitAI,
checkpoints/loras/vae), `list_local_models`, `search_custom_nodes`,
`install_custom_node`, `get_workflow`, `save_workflow`, `visualize_workflow`.
Для видео — `ffmpeg-skill` MCP (`probe`, `cut`, `fit`, `caption`, `graphics`).
Для PDF проще прямой PIL-пайплайн.

Для веб-поиска включён **`ddg-search`** (DuckDuckGo MCP):
`web_search(query)` и `web_fetch(url)` в чате.

Веб-исследование работает автоматически: если в запросе есть «поищи / найди в
интернете / погугли» или это технический вопрос про ComfyUI, LoRA, ноды, модели,
ошибки и решения воркфлоу, робот без дополнительных напоминаний:

1. формулирует 1–2 коротких поисковых запроса;
2. ищет через DuckDuckGo;
3. читает 1–2 самые релевантные страницы (`fetch_content`, при ошибке — прямой
   HTTP-запрос с очисткой HTML);
4. отвечает шагами со ссылками и честно говорит, если факта в источниках нет.

Отдельный тул-луп больше не упирается в «Слишком много шагов»: при исчерпании
шагов или повторах вызовов робот формулирует ответ по уже собранным данным.

Альтернативы ComfyUI MCP: официальный `Comfy-Org/comfy-mcp` (локальный контроль,
download по URL) и `ConstantineB6/comfy-pilot` (редактирование live-графа).

Робот также умеет создавать сущности и задачи через synx API:
`synx_create_entity` (asset/shot, с автоподбором кода `asset_type` по label),
`synx_create_task` (с назначением бота) и `synx_asset_types`/`synx_task_types`
для проверки допустимых типов. Пример: ассет `main_script` типа `Script` в
`test_proekt_vfx` с описанием «разработка главного сценария фильма».

## Фокус чата и защита от лишних публикаций

- Робот запоминает project/shot/version из текущего сообщения (таблица
  `chat_focus`) и показывает их модели как «Текущий фокус».
- История чата короткая (16 сообщений), а при явной смене шота/версии старые
  сообщения отрезаются — древние версии и прошлые PDF-эксперименты больше не
  всплывают в новом запросе.
- Публикация разрешена только по явной команде («опубликуй», «сделай версию»,
  «запушь»). Упоминание версии — референс, а не разрешение публиковать.
- Если запрос называет один шот, а инструмент пытается опубликовать другой,
  публикация блокируется с ошибкой `focus_mismatch`.
- Запрос «возьми версию X за основу и собери воркфлоу» обрабатывается
  детерминированно: находится именно эта версия, скачивается референс-кадр,
  ничего не публикуется; при выключенном ComfyUI робот честно об этом пишет.
- Правки PDF («чёрные листы», «текст мельче», «кадр по центру», 300 dpi)
  распознаются и без слова «pdf», поэтому не уходят в тул-луп.

## Synx API для робота

Актуальный справочник API лежит в `prompts/synx_api.md` и подмешивается в
системный промпт чата: проекты, сущности, задачи, версии, комментарии,
события, личные сообщения, task_types, assignments-form (скилы ботов),
публикации задачи, публикация версии, media kinds и формат плейлиста.

Важно для PDF: после публикации робот проверяет `media.kind`. Если synx
вернул `null`, PDF не распознан для этой сущности/типа задачи — плеер может
показать пустоту; нужен preview (контактный лист/слайдшоу) или PDF-friendly
задача/asset. Сам PDF при этом проверяется по страницам и размеру.

## Synx-инструменты в чате

Чат использует данные Synx из настроек (`base_url`, логин, пароль) и умеет:

- `synx_projects` — список проектов;
- `synx_find_version` — точный поиск версии по project + shot + version;
- `synx_versions` — версии проекта за период (можно фильтровать по shot/version);
- `synx_tasks` — задачи проекта;
- `synx_make_playlist` — плейлист Synx Player за период;
- `generate_from_synx_version` — скачать версию, взять кадр и сгенерировать
  изображение одним вызовом;
- `synx_project_news` — сводка по локальной таблице за период;
- `synx_bots` — настроенные боты, их скилы и доступность в synx;
- `make_pdf_from_images` — склейка картинок в PDF;
- `publish_images_as_version` — PDF + задача + бот + раскладка файлов + версия.

Плейлист формируется по формату `synx_engine`:

```text
<start synx playlist:
{"synx_playlist": 1, "items": [...]}
end synx playlist>
```

В чате он показывается карточкой с кнопкой **«Скопировать»**. Текст можно
вставить в плейлист Synx в браузере (Ctrl+V).

### Сводка «что нового»

Если спросить «что нового в проекте … за …», робот сначала вызывает
`synx_project_news` — читает уже собранную локальную таблицу, сравнивает с
последним просмотром этого чата (`project_views.last_seen_id`) и отдаёт:

- сколько новых сообщений с прошлого просмотра (`first_view` для первого раза);
- продолжения, отвеченные, версии и упоминания `@p.robot`;
- топ шотов по активности (ближайший фронт работ);
- список действий, упоминаний и последних версий;
- текстовый digest, по которому модель делает краткое резюме.

## Сессии чата

История чата хранится в SQLite и переживает перезапуск приложения. Каждая
сессия имеет свой контекст; сессии можно создавать и переключать в верхней
панели чата. Модель при каждом запросе получает историю текущей сессии.


## Темы

Кнопка **◐** в верхней панели открывает меню тем из synx_engine:

- Redmond;
- Ash;
- Dark;
- cs 1.6;
- своя тема.

Пункт **«Редактор тем…»** открывает диалог с загрузкой картинки-источника,
ручным выбором цветов, кнопкой **Sample!** (сэмплирование четырёх цветов
с картинки), предпросмотром, сохранением/загрузкой `.json` и применением.
Тема сохраняется в localStorage/куке и применяется при следующем запуске.


## Разметка публикаций

При сканировании новые комментарии автоматически отправляются AI-разметке
(`synx.auto_analyze`). Для каждого определяется:

- **продолжение** — нужна новая версия/генерация/исправление;
- **версия** — публикация версии, уведомление или положительный отзыв.

Если после комментария по тому же шоту уже выпущена версия (для комментариев
задачи — версия этой же задачи), комментарий считается **отвеченным версией**.
Такой комментарий не требует продолжения, задача по нему не предлагается и не
создаётся. При сканировании флаги отвеченных комментариев обновляются
автоматически, повторный ручной разбор не нужен.

В таблице публикаций есть колонка **«Тип публикации»** и фильтры:

- все события;
- с продолжением;
- просто версия;
- не разобрано;
- отвечено версией;
- с картинками;
- чекбоксы «Показывать версии» и «Показывать отвеченные».

Отвеченные комментарии по умолчанию скрыты из таблицы. Существующие
неразобранные комментарии можно отправить в AI-разметку кнопкой
**«Разметить AI»**.

### Приоритетные сообщения @p.robot

Сканер ищет упоминания `@p.robot` в комментариях версий, задачах,
комментариях сущностей и в свежей ленте событий synx. Такие сообщения
считаются приоритетными указаниями:

- помечаются в таблице бейджем **`@p.robot`** и фильтром
  «упоминания @p.robot»;
- всегда классифицируются как «с продолжением», даже если в тексте нет
  обычных слов-триггеров;
- автоматически ставятся в AI-разбор, который формирует конкретное
  руководство к действию (summary/prompt) на основе текста сообщения;
- задачи из таких сообщений получают приоритет и запускаются конвейером
  раньше обычных;
- если по сообщению уже выпущена версия, оно считается отвеченным и задача
  не создаётся.
